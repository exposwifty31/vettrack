## Step 1 — Rotate Clerk production keys FIRST

Do this before the history scrub, so the old keys in history are already dead.

> **`CLERK_SECRET_KEY` lives on TWO production services, not one.** `VetTrack`
> (`551051c2-…`) and `Worker` (`227407ca-…`) both hold it. Rotating one and forgetting
> the other leaves that service on a key that dies when the grace window closes.
> Re-derive the list before starting rather than trusting this note — but **not with
> `railway variable list --kv`**: that flag prints raw values, so using it to find out
> *which* services hold a secret dumps the secret itself into your terminal and
> scrollback. Ask only whether the key is set, and compare by fingerprint:
>
> ```bash
> for svc in $(railway service list --json | jq -r '.[].id'); do
>   v=$(railway variable list --kv -p "$P" -e "$E" -s "$svc" | sed -n 's/^CLERK_SECRET_KEY=//p')
>   [ -n "$v" ] && printf '%s holds it, sha=%s\n' "$svc" "$(printf %s "$v" | shasum -a 256 | cut -c1-12)"
> done
> ```
>
> The value stays inside `$v`; only a 12-character digest is ever printed, which is
> also what you compare against after writing the new key.

1. Rotate. Either the dashboard (**API Keys → Secret keys → Roll secret key** on the
   production instance `clerk.vettrack.uk`) or, scriptable and auditable, the Platform
   API — which also takes a grace window and a reason:
   `clerk api "/platform/applications/<app>/instances/<ins>/rotate_secret_keys" --platform --yes -d '{"delay_old_secrets_expiration_hours":1,"reason":"…"}'`
2. **Set a grace window.** With `delay_old_secrets_expiration_hours: 1` the old key
   stays valid while you propagate, so a failed deploy cannot take production auth
   down and you can retry. Without it, any propagation failure is an outage.
3. Write the new key to **every** service from the list above, reading it from stdin so
   it never becomes an argv entry, a shell-history line, or a file. Populate and guard
   the variable explicitly — an unset `NEW` silently writes an **empty** secret, which
   production validation then rejects at startup:

   ```bash
   trap 'unset NEW' EXIT INT TERM
   read -r -s -p "New Clerk key: " NEW; printf '\n'
   case "$NEW" in sk_live_*) ;; *) echo "refusing: not an sk_live_ key" >&2; exit 1 ;; esac

   # every service the enumeration above reported as holding the key
   SERVICES="551051c2-fcda-47f8-9823-1d95455a5e3e 227407ca-9edf-4162-bbcc-efe39461cfdf"
   for svc in $SERVICES; do
     printf '%s' "$NEW" | railway variable set CLERK_SECRET_KEY --stdin \
       -p "$P" -e "$E" -s "$svc" --skip-deploys || exit 1
   done
   ```

   `--skip-deploys` is required here, not optional — see step 4 for why, and for the
   redeploy that must follow it.
4. **Deploy a known-good image and verify before the window closes** — this is the step
   that matters. A variable change alone does not reach the running process, and on this
   project a Railway-initiated redeploy of a production service cannot succeed (they
   carry no `source.repo` by design). Use
   `deploymentRedeploy(id: <last SUCCESS>, usePreviousImageTag: true)`, which reuses the
   built image and needs no repository snapshot.
5. Verify by fingerprint, never by printing values: read the variable back on each
   service and compare `shasum -a 256` against the new key's.
6. **The discriminating check.** While the grace window is open, `/api/health` reports
   `clerk: ok` for *either* key, so it proves nothing. Wait for the old key to return
   **401** from `GET https://api.clerk.com/v1/instance`, then confirm `/api/health` is
   still `clerk: ok`. That single pair of observations is the proof the running process
   holds the new key.
7. Only then redact the value from the repository. A redaction pushed while the old key
   still works is a signpost, not a fix.

> **Note:** The public key (`pk_live_*`) is not a secret — it is safe in public git history. Only the `sk_live_*` key is sensitive. Rolling it is sufficient.

## Step 2 — Scrub git history

> **Cost, measured 2026-08-19 — read before running any of this.** The value is in
> the tree of **1,915 of 2,655** commits on `main` (72%). `filter-repo` rewrites
> every one of them, so every SHA after 2026-04-17 changes: open PRs need rebasing,
> every clone and worktree must be re-cloned, and existing forks keep the old
> objects regardless. Because the key is already rotated and dead, the scrub buys
> only tidiness of the historical record, not security. Treat it as an owner
> decision with a real coordination cost, not an automatic follow-up.


```bash
# From repo root
cd /path/to/VetTrack || exit 1

# Verify the key appears in history.
# Do NOT search for the placeholder above — it is not the key, so a clean result
# would be a false negative. And do NOT pass -p: it prints the matching patches,
# re-exposing the value in your terminal and scrollback. Read the value into a
# variable from a hidden prompt and print commit ids only.
set -o pipefail
trap 'unset CLERK_OLD_KEY' EXIT INT TERM
read -r -s -p "Old Clerk key: " CLERK_OLD_KEY; printf '\n'
git log --all --pretty=format:%H -S"$CLERK_OLD_KEY" || exit 1

# Run filter-repo to remove the string from ALL history
# Replace the actual key value with the literal string to scrub
git filter-repo --replace-text <(echo '==>REMOVED==') \
  --force

# Alternatively, to scrub specific files from history:
git filter-repo --path .env.production --invert-paths --force
```

> Using `--path .env.production --invert-paths` is safer: it removes the file entirely from all history rather than doing text replacement, which can leave partial matches.

## Step 5 — Verify

```bash
# Confirm neither secret appears in any branch or tag.
#
# Two things matter here beyond the search itself. `git log ... | head -5` reports
# head's exit status, so a git failure reads as "no output" — a clean result that is
# really a broken command. Use --max-count and check the status. And never pass -p:
# it prints the matching patches, re-exposing exactly what you are hunting for.
set -o pipefail
trap 'unset CLERK_OLD_KEY OLD_SESSION_SECRET' EXIT INT TERM

read -r -s -p "Old Clerk key: " CLERK_OLD_KEY; printf '\n'
git log --all --max-count=5 --pretty=format:%H -S"$CLERK_OLD_KEY" || exit 1
# Expected: no output

read -r -s -p "Old SESSION_SECRET: " OLD_SESSION_SECRET; printf '\n'
git log --all --max-count=5 --pretty=format:%H -S"$OLD_SESSION_SECRET" || exit 1
# Expected: no output
```
