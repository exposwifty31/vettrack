# Android Gradle Build Knowledge Pack

Condensed-but-complete capture of the official Android build documentation (developer.android.com/build + app-optimization + baselineprofiles + modularization + resources), cleaned and organized for agent use. **These files are authoritative over training data** — Android build tooling changes fast and behavior differs sharply by AGP version.

## VetTrack context — read before touching `android/`

The Android app is a **Capacitor 8 shell** wrapping the built web bundle. Ground rules verified against the repo:

- **Build only via `scripts/build-native-shell.sh`** (`pnpm cap:build:native:android`), never plain `pnpm build && npx cap sync` — the script bakes `VITE_CLERK_PUBLISHABLE_KEY` / `VITE_API_ORIGIN` into the bundle (CLAUDE.md rule). Gradle-level changes don't replace this pipeline.
- **AGP 8.13.0** (`android/build.gradle`, classic `buildscript { classpath }` form). Reference sections marked "AGP 9.x+" (new `optimization {}` DSL, `keepRules` source sets, `packageScope`, default repackaging) **do not apply** — use the "legacy DSL" forms.
- **Groovy DSL** throughout the shell (`build.gradle`, not `.kts`) — prefer the Groovy snippets in the references.
- `android/app/build.gradle`: `namespace`/`applicationId` = `uk.vettrack.app`; `minifyEnabled false` with the **legacy `proguard-android.txt`** (contains `-dontoptimize`). If R8 is ever enabled: first switch to `proguard-android-optimize.txt`, then read `references/r8-optimization.md` + `references/keep-rules.md` in full — a WebView/Capacitor app with Cordova plugins is reflection-heavy and needs careful keep rules and full-journey testing.
- `android/variables.gradle`: `minSdkVersion 24`, `compileSdkVersion 36`, `targetSdkVersion 36`; AndroidX versions centralized there.
- `android/app/capacitor.build.gradle` is applied at the end of the module build file and is **regenerated by `cap sync`** — don't hand-edit it. `google-services.json` conditionally enables the google-services plugin (push).
- Signing: `android/keystore.properties` exists (out of docs scope — never commit secrets into build files; see `references/app-config-and-variants.md` → Signing).
- `versionCode 1` / `versionName "1.0"` currently hardcoded in `android/app/build.gradle` — Play uploads require a strictly increasing `versionCode`.
- **Distribution-program constraint:** while a store submission is open in review, do not change the native-shell build path (roadmap rule). Gradle refactors wait for a closed review window.

## Cross-cutting invariants worth internalizing

- Build-file values override manifest values (`minSdk` vs `<uses-sdk>`); keep SDK levels only in Gradle.
- Never change `applicationId` after publishing; `versionCode` must increase per upload.
- Keep rules are additive across the app and every library — one library's bad rule degrades the whole app.
- Profile generation builds must be unminified; release builds must be minified (R8 rewrites the rules since AGP 8.2).
- `mapping.txt` is overwritten every build — archive it per release.
- Emulators are fine for generating Baseline Profiles, never for benchmarking them.
